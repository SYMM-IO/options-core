## 1. Threat Model Overview

| Actor                                               | Motive                                                                                                                                                                     | Primary surface                                                                                                                                                                                                                                    |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Party A (rational user)                             | Open favorable options, exit via close, NFT transfer, or settlement                                                                                                        | `PartyAOpenFacet`, `PartyACloseFacet`, `TradeFacet`                                                                                                                                                                                                |
| Party A (adversarial)                               | Trick Party B into a worse-than-agreed fill, replay signed ops, exfiltrate via withdraw before liquidation                                                                 | Open intent threshold, settlement signature, NFT transfer to Party B                                                                                                                                                                               |
| Party B (active solver)                             | Lock and fill profitable intents, win partial fills, claim premium                                                                                                         | `PartyBOpenFacet`, `PartyBCloseFacet`, `lockOpenIntent` race                                                                                                                                                                                       |
| Malicious Party B                                   | Lock-and-stall to deny fills; under-collateralize then go silent; fill at the worst legal price; grief residual open intents; abuse exclusive settlement window            | `lockOpenIntent` / `unlockOpenIntent`, fill price threshold (`InvalidOpenPrice` `contracts/libraries/core/LibPartyBOpen.sol:216`), child-intent residual handling, `PartyBExclusiveWindow` (`contracts/libraries/core/LibTradeOperations.sol:159`) |
| Malicious solver / MEV bot                          | Frontrun Party A intents; race force-cancel at exact timeout; sandwich settlement                                                                                          | `ForceActionsFacet`, `TradeFacet.executeTrades`, `lockOpenIntent`                                                                                                                                                                                  |
| Malicious affiliate                                 | Get whitelisted then redirect fees to an attacker-controlled collector                                                                                                     | `setAffiliateFeesCollector` (`contracts/facets/Control/ControlFacet.sol:354`); requires `AFFILIATE_MANAGER_ROLE` to be granted                                                                                                                     |
| Malicious admin (`DEFAULT_ADMIN_ROLE`)              | Grant arbitrary roles; rewrite fee collectors; whitelist a draining external transfer target; swap signature verifier or oracle                                            | `ControlFacet` admin surface (see Section 2)                                                                                                                                                                                                       |
| Malicious clearing house (`CLEARING_HOUSE_ROLE`)    | Confiscate solvent counterparty; mis-distribute pool; close open trades at off-market prices supplied as `prices[]`                                                        | `ClearingHouseFacet.confiscate`, `closeTrades`, `distributeCollateral` (constrained by `DistributedAmountExceedsConfiscatedAmount` invariant — `contracts/libraries/core/LibClearingHouse.sol:305`)                                                |
| Compromised InstantLayer operator (`OPERATOR_ROLE`) | Replay or reorder signed ops, sandwich Party A actions inside the `callFromInstantLayer` window                                                                            | `InstantLayer.executeBatch` / `executeTemplate` (`contracts/helpers/InstantLayer.sol:311,354`); bounded by EIP-712 + `usedOperationHashes`                                                                                                         |
| Muon TSS attacker (quorum compromise)               | Forge `UpnlSig` / settlement-price sig to fake liquidation, fake exercise PnL, or pass deallocate solvency check                                                           | `LibMuon.verifyUpnlSig` (`contracts/libraries/services/LibMuon.sol:59-92`), settlement path in `TradeFacet.executeTrades`                                                                                                                          |
| Compromised gateway signer                          | Same as TSS compromise downstream — `MuonOracle` requires the gateway signature alongside Schnorr                                                                          | `MuonOracle` (`contracts/helpers/MuonOracle.sol:38-43`)                                                                                                                                                                                            |
| Malicious `IPriceOracle`                            | Misprice fee token, causing Party A to overpay or underpay open-intent fees                                                                                                | `getPriceOracleAddress` (`contracts/facets/View/ViewFacet.sol:244`); used inside `LibPartyAOpen` fee math                                                                                                                                          |
| Malicious `IExpressWithdrawProvider`                | Reject valid express withdrawals (DoS) or report inflated `validAmount` (capped by `ValidAmountExceedsOriginal` — `contracts/libraries/core/LibBalanceOperations.sol:170`) | `initiateExpressWithdraw` (`contracts/facets/Account/AccountFacet.sol:174`)                                                                                                                                                                        |
| Malicious `IExternalTransferTarget`                 | Receive funds and refuse to credit, or re-enter on receipt                                                                                                                 | `externalTransfer` (`contracts/facets/Account/AccountFacet.sol:125`); guarded by `nonReentrant` and per-collateral whitelist                                                                                                                       |

## 2. Trust Assumptions

The protocol is trust-minimized at the facet API boundary but trusts a small set of admin keys and external services. Any compromise of the rows below has immediate or near-immediate fund-loss potential.

| Trust anchor                         | Why it matters                                                                                                                                                                                                                                                                                                                                                                      | Reference                                                                                                                    |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Diamond owner (`LibDiamond`)         | Sole caller of `setAdmin` and `diamondCut`. A compromised owner can replace any selector, including liquidation, settlement, withdraw.                                                                                                                                                                                                                                              | `contracts/facets/Control/ControlFacet.sol:53-57`, `contracts/libraries/core/LibDiamond.sol:68`                              |
| `DEFAULT_ADMIN_ROLE`                 | Grants and revokes every other diamond role. Compromise transitively grants every other role below.                                                                                                                                                                                                                                                                                 | `contracts/facets/Control/ControlFacet.sol:65-89`                                                                            |
| `SETTER_ROLE`                        | Owns timing parameters (`forceCancel*Timeout`, `partyBExclusiveWindow`, `upnlSigValidTime`, `settlementPriceSigValidTime`), fee collector, **signature verifier address** (`contracts/facets/Control/ControlFacet.sol:871`), express-withdraw provider config, invalid-withdrawals pool. Compromise can shorten timeouts, replace the EIP-1271 verifier, or redirect protocol fees. | [[roles-and-pauses#Part 1 — Roles]]                                                                                          |
| `PARTY_B_MANAGER_ROLE`               | Activates Party Bs; sets `lossCoverage` (controls when Party B is declared insolvent); sets `oracleId`. Compromise can either prevent legitimate liquidation (`lossCoverage=0` blocks `flag*` with `ZeroLossCoverage`) or activate a malicious Party B address.                                                                                                                     | `contracts/facets/Control/ControlFacet.sol:392-411`                                                                          |
| `SYMBOL_MANAGER_ROLE`                | Lists symbols, flips validity, mutates per-symbol platform fees. A malicious listing can pair an option with a hostile collateral or oracle.                                                                                                                                                                                                                                        | `contracts/facets/Control/ControlFacet.sol:755-852`                                                                          |
| `ORACLE_MANAGER_ROLE`                | Adds and **mutably overwrites** oracle addresses (`updateOracle` at `contracts/facets/Control/ControlFacet.sol:721`); sets the global `IPriceOracle`. Compromise can repoint pricing under live trades.                                                                                                                                                                             | `contracts/facets/Control/ControlFacet.sol:706-736`                                                                          |
| `PAUSER_ROLE`                        | Can halt every flow (12 pause flags) and put any Party B in emergency mode. Used to stop loss; cannot move funds.                                                                                                                                                                                                                                                                   | [[roles-and-pauses#Part 2 — Pause Flags]]                                                                                    |
| `UNPAUSER_ROLE`                      | Can prematurely lift pauses or emergency. Should be a higher-trust key than pauser.                                                                                                                                                                                                                                                                                                 | Same                                                                                                                         |
| `SUSPENDER_ROLE`                     | Per-address freeze and per-withdrawal freeze. Cannot edit balances; can only deny access until disputer rules.                                                                                                                                                                                                                                                                      | `contracts/facets/Control/ControlFacet.sol:654-676`, `contracts/facets/Account/AccountFacet.sol:200`                         |
| `DISPUTER_ROLE`                      | The only role that can rewrite the `validAmount` on a suspended withdrawal (`AccountFacet.restoreWithdraw` at `:211`). Excess is routed to the invalid-withdrawals pool. Compromise can route arbitrary amounts of a flagged withdrawal back to the user.                                                                                                                           | `contracts/facets/Account/AccountFacet.sol:211`                                                                              |
| `CLEARING_HOUSE_ROLE`                | Sole caller of every `ClearingHouseFacet` selector. Picks the `prices[]` for `closeTrades` (no on-chain price check), drives `confiscate`/`distributeCollateral`. Compromise can mis-settle a real liquidation; cannot mint collateral (conservation invariant `confiscatedAmount >= distributedAmount` at `contracts/libraries/core/LibClearingHouse.sol:305`).                    | [[liquidation-and-force-actions]]                                                                                            |
| `VIRTUAL_DEPOSITOR_ROLE`             | Can credit isolated balance to any user without an actual ERC-20 transfer (`AccountFacet.virtualDepositFor` at `:51`). Compromise allows minting accounting balance up to `balanceLimitPerUser` and withdrawing real protocol collateral after release.                                                                                                                             | `contracts/facets/Account/AccountFacet.sol:51-55`                                                                            |
| `INSTANT_LAYER_ROLE`                 | Toggles `AppStorage.callFromInstantLayer`, which bypasses `whenInstantModeIsNotActive` for nested calls. Must be granted only to the deployed `InstantLayer` address.                                                                                                                                                                                                               | `contracts/facets/Control/ControlFacet.sol:937-938`                                                                          |
| `OPERATOR_ROLE` (InstantLayer)       | Calls `executeTemplate` / `executeBatch`. Replay-bounded by EIP-712 sig + `usedOperationHashes`; ordering inside a batch is operator-chosen.                                                                                                                                                                                                                                        | `contracts/helpers/InstantLayer.sol:311,354,401-402`                                                                         |
| Muon TSS quorum                      | Signs `UpnlSig` (deallocate solvency, liquidation insolvency) and `SettlementPriceSig` (option settlement). Quorum compromise is equivalent to forging PnL and settlement prices.                                                                                                                                                                                                   | `contracts/libraries/services/LibMuon.sol`, `contracts/helpers/MuonOracle.sol`                                               |
| Muon gateway signer                  | Co-signs the Muon report inside `MuonOracle`. Compromise alone doesn't forge a sig (Schnorr is required) but can grief by withholding.                                                                                                                                                                                                                                              | `contracts/helpers/MuonOracle.sol:43`                                                                                        |
| `IPriceOracle` integrity             | Used during open-intent creation to convert fee token to collateral. A bad price doesn't move locked premium but mis-sizes platform/affiliate fees.                                                                                                                                                                                                                                 | `contracts/libraries/core/LibPartyAOpen.sol` (fee math)                                                                      |
| `IExpressWithdrawProvider` integrity | Holds custody during express settlement. Provider can refuse (`ExpressWithdrawRejectedByProvider`) or reduce the redeemable amount; never inflate beyond original.                                                                                                                                                                                                                  | `contracts/libraries/core/LibBalanceOperations.sol:128-170`                                                                  |
| `IExternalTransferTarget` integrity  | Receives funds during `externalTransfer`. The target's `deposit` is called after the ERC-20 transfer; if it reverts, the whole transaction reverts. Whitelisted per `(target, collateral)` pair.                                                                                                                                                                                    | `contracts/facets/Account/AccountFacet.sol:125`, target validation at `contracts/libraries/core/LibBalanceOperations.sol:93` |
| `SignatureVerifier` (mutable)        | Shared EOA / ERC-1271 verification helper. Replaceable by `SETTER_ROLE` via `setSignatureVerifier` — any swap immediately changes how every protocol-wide signature check resolves.                                                                                                                                                                                                 | `contracts/facets/Control/ControlFacet.sol:871`                                                                              |
| `TradeNFT` address                   | Configured by `SETTER_ROLE` (`setTradeNftAddress` `:285`). Only this address is allowed to call `transferTradeFromNFT`. A malicious NFT contract can rewrite trade ownership.                                                                                                                                                                                                       | `contracts/facets/Trade/TradeFacet.sol:45`                                                                                   |

## 4. Key Invariants

## 5. Reentrancy Posture

- The guard sits in `contracts/utils/ReentrancyGuard.sol:14`, backed by `AccessControlStorage.reentrancyGuardStatus`. Reverts with `ReentrancyGuardErrors.ReentrantCall`.
- `nonReentrant` is applied to every call that performs an external token transfer or external contract call back to a mutable counterparty contract:
    - `AccountFacet.deposit` / `depositFor` / `externalTransfer` / `initiateExpressWithdraw` / `completeWithdraw` (`contracts/facets/Account/AccountFacet.sol:39, 74, 132, 182, 223`).
    - `TradeFacet.transferTrade` / `mintNFTForTrade` (`contracts/facets/Trade/TradeFacet.sol:32, 71`).
- **Not** guarded:
    - `PartyB*Facet` and `PartyA*Facet` entrypoints (no external call out beyond storage).
    - `ClearingHouseFacet` (operator-only; no external calls).
    - `TradeFacet.executeTrades` and `transferTradeFromNFT` (they read state and mutate; settlement does not call out to user-controlled contracts directly, but `transferTradeFromNFT` can only be invoked by the configured TradeNFT and so reentrancy depends on TradeNFT correctness).
- The guard storage is shared across the diamond (single slot in `AccessControlStorage`), so re-entry between facets is also blocked while one guard is held.

## 6. Pause Model

Defense-in-depth is provided by twelve independent pause flags in `StateControlStorage` (`contracts/storages/StateControlStorage.sol:10-28`). `globalPaused` is the kill switch checked first by every `Pausable` modifier. See [[roles-and-pauses#Part 2 — Pause Flags]] for the full mapping of flag → modifier → setter.

Operational implications:

- `pauseGlobal` is the broadest stop-loss; all pause unwinds require `UNPAUSER_ROLE`, which should be a more conservative key than `PAUSER_ROLE`.
- Per-domain pauses (deposit, withdraw, internal/external transfer, express withdraw, party A actions, party B actions, third-party actions, liquidating, instant layer) let an incident response halt one bug class without freezing the whole protocol.
- Pause does not move balances. Funds locked at the time of pause stay locked under their normal release model.

## 7. Suspension Model

Suspension is per-address or per-withdrawal and is **not** the same as pause or liquidation flagging. See [[roles-and-pauses#Part 4 — Suspension and Emergency]].

- **Address suspension** (`suspendedAddresses[user]`) blocks the user from initiating deposits, transfers, withdrawals, allocations, deallocations, and trade transfers (full list at `contracts/utils/Accessibility.sol:53-69`). Suspended users can still be liquidated.
- **Withdrawal suspension** (`suspendedWithdrawal[withdrawId]`) freezes one specific pending withdrawal so it can be reviewed before completion or cancellation.
- Suspender flow: `SUSPENDER_ROLE` flips the flag (`AccountFacet.suspendWithdraw` at `:200`, `ControlFacet.suspendWithdrawal` at `:665`).
- Disputer flow: `DISPUTER_ROLE` calls `AccountFacet.restoreWithdraw(id, validAmount)` at `:211`. This clears the suspended flag and **rewrites** `Withdraw.amount` to `validAmount`. The difference between the original and `validAmount` is routed to `getInvalidWithdrawalsPool` (`contracts/facets/View/ViewFacet.sol:144`). The disputer is the only role that can reduce a withdrawal's claimable amount; the suspender can only freeze/unfreeze.
- The suspender alone cannot redirect funds. The disputer can redirect a portion to the invalid pool but not to an arbitrary address.

## 8. Emergency States

Party B emergency mode is a focused freeze on opening new exposure with a problematic Party B. See [[roles-and-pauses#Party B emergency mode]].

- Two storage levels: `partyBsEmergencyMode` (global) and `partyBEmergencyMode[partyB]` (single Party B), at `contracts/storages/StateControlStorage.sol:23-24`.
- Both are checked inside `LibPartyBOpen` lock (`:51-52`) and fill (`:184-185`). Reverts with `PartyBInEmergencyMode(partyB)` or `PartyBsInEmergencyMode()`.
- Emergency mode does **not** block close-side flows, withdrawals, or liquidation. It is specifically meant to stop a Party B from accepting new positions while still letting existing positions wind down.
- Activated by `PAUSER_ROLE`, deactivated by `UNPAUSER_ROLE`. Distinct from `pausePartyBActions`, which freezes every Party B for every action.

## 10. Signature Schemes Risk

For deeper recap see `docs/concepts/oracle-and-signatures.md` (planned). Three independent signature schemes are in use:

- **Muon TSS** for `UpnlSig` and `SettlementPriceSig` (`contracts/libraries/services/LibMuon.sol`, verified through `MuonOracle.sol:38-43` which combines a Schnorr signature with a gateway ECDSA signature). Risks: TSS quorum compromise, gateway compromise (gateway alone cannot forge), expired signatures (`ExpiredSignature` at `LibMuon.sol:32,66`), and replay (settlement-side replay blocked by `isSigUsed`; uPnL replay blocked by bilateral nonce — `LibMuon.sol:85`).
- **EIP-712 / EIP-1271** for `InstantLayer` signed operations (`contracts/helpers/InstantLayer.sol`). Risks: signer key compromise, deadline expiry (`DeadlineExpired` at `:387`), nonce/salt collisions (replay blocked at `:401-402`, ordering at `:410`).
- **EOA / ERC-1271** general signatures via `SignatureVerifier` (backed by `LibSignatureChecker`) and `LibSignature`. Risks: a compromised contract signer (notably MultiAccount-owned SymmioPartyA, which delegates ERC-1271 back to MultiAccount); `SignatureVerifier` replacement by `SETTER_ROLE`.

Signature checks deliberately keep OpenZeppelin 4 semantics through `contracts/libraries/utils/LibSignatureChecker.sol`: ECDSA `tryRecover` first, then ERC-1271. This lets an EIP-7702-delegated EOA, which has code, still sign with its own key. OpenZeppelin 5's stock `SignatureChecker` routes on `signer.code.length` and would reject those signatures, so `LibSignatureChecker` must not be replaced with it without an explicit decision.

## 11. Decimal Normalization

`LibDecimals` (`contracts/libraries/utils/LibDecimals.sol`) is the single source of normalization. All deposits and withdrawals normalize/denormalize between collateral decimals and the protocol's 1e18 internal precision:

- `normalizeAmount(token, amount) = (amount * 1e18) / 10**decimals` (`LibDecimals.sol:13-16`)
- `denormalizeAmount(token, amount) = (amount * 10**decimals) / 1e18` (`LibDecimals.sol:18-21`)

Both use Solidity 0.8.19 integer division and **truncate**. Known consequences:

- A withdrawal of less than `10**(18-decimals)` of a low-decimal token (e.g. USDC at 6 decimals: `10**12` units of internal value) denormalizes to zero — the user effectively forfeits dust on withdrawal.
- A deposit-then-withdraw round trip is not amount-preserving for amounts below the granularity of the token; this is a property of any fixed-precision normalization.
- All other internal math (premium, fee, MM) is in 1e18 collateral units; reads via `IERC20Metadata(token).decimals()` are made every call (no decimals cache), trusting the token to report a stable value.

## 14. Auditor's Quick Map

If you have **1 day**, audit:

1. `contracts/facets/Trade/TradeFacet.sol:61` (`executeTrades`) and `contracts/libraries/core/LibTradeOperations.sol` settlement path. Settlement is anyone-callable, signature-driven, and ends every trade — getting this wrong loses funds at expiry.
2. `contracts/facets/ClearingHouse/ClearingHouseFacet.sol` and `contracts/libraries/core/LibClearingHouse.sol`. Liquidation, confiscation, distribution. Verify the `confiscatedAmount >= distributedAmount` invariant (`LibClearingHouse.sol:305`) and the `address(0)` Party A path for isolated Party B.

If you have **1 week**, additionally audit:

3. `contracts/libraries/core/LibPartyBOpen.sol` `fillOpenIntent` (`:164-378`) — premium math, residual creation, partial-fill accounting, locked-balance bookkeeping, and deferred Party B sell escrow consumption.
4. `contracts/libraries/core/LibPartyBClose.sol` `fillCloseIntent` — PnL computation and bilateral nonce increment (`:170-171`).
5. Scheduled release (`contracts/libraries/models/LibScheduledReleaseBalance.sol`) — `subForCounterParty`, `scheduledAdd`, `decreaseMM`, the timestamp invariants at `:337` and `:382`. This is the most arithmetic-dense file in the protocol.
6. `contracts/helpers/InstantLayer.sol` — replay protection (`:401-410`), template result splicing (`executeTemplate` at `:311`), the `setCallFromInstantLayer` toggle pairing.
7. `contracts/libraries/services/LibMuon.sol` and `contracts/helpers/MuonOracle.sol` — Schnorr verification, gateway co-signing, the bilateral-nonce-bound payload at `:85`.

If you have **a month**, additionally audit:

8. `contracts/libraries/core/LibAllocationOperations.sol` — cross-margin solvency and debt-coverage logic (`:107-137`).
9. `contracts/facets/Control/ControlFacet.sol` admin surface in full — every setter is a potential griefing vector.
10. `contracts/helpers/MultiAccount.sol` and `contracts/helpers/SymmioPartyB.sol` — selector-restriction logic, ERC-1271 delegation, multicast whitelist.
11. The full pause / suspension / emergency matrix, walking each modifier against every function in [[facets]].
